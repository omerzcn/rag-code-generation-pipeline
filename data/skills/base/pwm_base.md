### WHAT IS PWM?

PWM stands for Pulse Width Modulation.

Instead of a pin being simply ON or OFF, PWM rapidly switches the pin
ON and OFF at a fixed frequency.
The ratio of ON time to total time is called duty cycle.

This allows the Pi to:
    - Control LED brightness smoothly
    - Control servo motor position precisely
    - Generate tones from a passive buzzer
    - Simulate a variable analog output on a digital pin

Important:
    - PWM is not a true analog signal.
    - PWM is a digital signal switching rapidly.
    - For most practical purposes it behaves like analog output.

### WHEN TO USE THIS SKILL

Use this skill when the output requires variable control:
    - LED brightness (not just on/off)
    - Servo motor position
    - Passive buzzer tone generation
    - Any output requiring duty cycle or frequency control

Do not use this skill for:
    - Simple on/off LED control (use digital_output)
    - Active buzzer on/off (use digital_output)
    - Relay modules (use digital_output)
    - Motor speed control beyond basic servo (use dedicated motor driver skill)
    - I2C or SPI devices

### WHEN NOT TO USE PWM

Do not use PWM if:
    - The load only needs to be ON or OFF.
    - The device is an active buzzer with internal oscillator.
    - The device requires I2C, SPI, or UART communication.
    - Precise analog voltage is required (use a DAC module instead).

Examples where PWM is wrong:
    - Active buzzers (they have internal oscillators)
    - Relay signal pins (only need on/off)
    - Digital sensors (they are inputs, not outputs)

### KEY CONCEPTS

Frequency

How many times per second the signal switches ON and OFF.
Measured in Hz (cycles per second).

    LED dimming: 100 to 1000 Hz works well
    Servo control: 50 Hz exactly (do not change this)
    Buzzer tones: frequency in Hz determines the pitch heard

Duty cycle

The percentage of time the signal is HIGH in one cycle.
In gpiozero the range is 0.0 to 1.0.

    0.0 = 0% always off
    0.25 = 25% low brightness or power
    0.50 = 50% half brightness or power
    0.75 = 75% high brightness or power
    1.0 = 100% fully on

Note:

Human eyes perceive LED brightness logarithmically.
A value of 0.1 looks roughly half as bright as 1.0.
This is normal and expected behavior.

Hardware PWM vs Software PWM

Hardware PWM:
    - Generated by dedicated Pi hardware timer.
    - Very precise and stable timing.
    - Available on GPIO 18 on all Pi models.
    - Also available on GPIO 19 (hardware PWM channel 1).
    - GPIO 18 and GPIO 19 share independent PWM channels.
    - Hardware PWM channel assignments:
    Channel 0: GPIO 18 and GPIO 12 (do not use both simultaneously)
    Channel 1: GPIO 19 and GPIO 13 (do not use both simultaneously)

    Using GPIO 18 does not conflict with GPIO 19.
    Using GPIO 12 does not conflict with GPIO 13.
    - Required for servo control.
    - Servos need precise 50 Hz timing or they jitter.

Software PWM:
    - Generated by the CPU in software.
    - Slightly less precise.
    - Can jitter under high CPU load.
    - Available on any GPIO pin.
    - Acceptable for LED dimming and buzzer tones.
    - Not reliable enough for servo control.

Rule: use GPIO 18 as the conventional servo pin.
Rule: any safe GPIO pin works for LED PWM dimming.
Rule: any safe GPIO pin works for buzzer tones.

Note on the actual PWM backend:
gpiozero uses software-timed PWM by default. Creating a Servo prints a
PWMSoftwareFallback warning - this is expected, not an error. True
hardware PWM traditionally needs the pigpio pin factory, which does NOT
support the Raspberry Pi 5. On a Pi 5 you get software-timed PWM
regardless of pin, which can jitter under CPU load. If servo jitter is a
problem, a dedicated driver (e.g. PCA9685 over I2C) is the usual fix, but
that adds an I2C device and its own skill file.

### PWM USE CASE REFERENCE TABLE

Use this table to choose the correct gpiozero class.

LED brightness control:
Class:PWMLED
Pin:any safe GPIO
PWM type:software PWM is fine
Value range:0.0 to 1.0

LED fade or breathing effect:
Class:PWMLED
Pin:any safe GPIO
PWM type:software PWM is fine
Value range:0.0 to 1.0

Servo position control:
Class:Servo
Pin:GPIO 18 only
PWM type:hardware PWM required
Value range:-1.0(min) to 0.0(center) to 1.0(max)

Passive buzzer tone:
Class:TonalBuzzer
Pin:any safe GPIO
PWM type:software PWM is fine
Value range:frequency in Hz, default A3 to A5 (about 220 to 880 Hz)
Tones outside the range raise ValueError
Extend the range with mid_tone and octaves

Active buzzer on/off:
Class:OutputDevice (see digital_output skill)
Pin:any safe GPIO
PWM type:not applicable
Note:active buzzers do not need PWM

### PATTERN 1 - LED BRIGHTNESS CONTROL

Use for setting LED to a specific brightness level.

from gpiozero import PWMLED
from time import sleep

PIN = 17    # any safe GPIO - hardware PWM not needed for LED

led = PWMLED(PIN)

print("Full brightness")
led.value = 1.0
sleep(1)

print("75 percent")
led.value = 0.75
sleep(1)

print("Half brightness")
led.value = 0.5
sleep(1)

print("Low brightness")
led.value = 0.1
sleep(1)

led.off()
print("Off")

### PATTERN 2 - LED FADE IN AND OUT

Use for smooth brightness transitions and breathing effect.

from gpiozero import PWMLED
from time import sleep

PIN = 17    # any safe GPIO - hardware PWM not needed for LED
STEPS = 20
DELAY = 0.05

led = PWMLED(PIN)

print("Fading in")
for i in range(STEPS + 1):
    led.value = i / STEPS
    sleep(DELAY)

print("Fading out")
for i in range(STEPS, -1, -1):
    led.value = i / STEPS
    sleep(DELAY)

led.off()
print("DONE")

### PATTERN 3 - SERVO BASIC POSITION CONTROL

Use for moving a servo to minimum, center or maximum.

Servo wiring (verify wire colors for your specific servo):
    - Brown or Black wire -> Pi GND (physical pin 6 or 9)
    - Red wire -> Pi 5V (physical pin 2 or 4)
    - Orange or Yellow -> GPIO 18 (BCM, signal only)

Important:
    - Always power servo from 5V pin, never from 3.3V.
    - Never power servo from a GPIO pin.
    - GPIO 18 carries only the signal, not power.
    - gpiozero Servo value range is -1.0 to +1.0.
        -1.0 = minimum position (approximately 0 degrees)
        0.0 = center position  (approximately 90 degrees)
        +1.0 = maximum position (approximately 180 degrees)

from gpiozero import Servo
from time import sleep

PIN = 18

servo = Servo(PIN)

print("Center")
servo.mid()
sleep(1)

print("Minimum")
servo.min()
sleep(1)

print("Maximum")
servo.max()
sleep(1)

print("Center again")
servo.mid()
sleep(1)

servo.detach()
print("DONE")

Note:

Call servo.detach() when done.
This stops the PWM signal and prevents servo jitter when the script is idle.

### PATTERN 4 - SERVO MOVE TO SPECIFIC ANGLE

Use for moving a servo to a calculated degree position.

from gpiozero import Servo
from time import sleep

PIN = 18

servo = Servo(PIN)

def move_to_angle(s, degrees):
    value = (degrees / 90.0) - 1.0
    if value < -1.0:
        value = -1.0
    if value > 1.0:
        value = 1.0
    s.value = value

print("Moving to 0 degrees")
move_to_angle(servo, 0)
sleep(1)

print("Moving to 90 degrees")
move_to_angle(servo, 90)
sleep(1)

print("Moving to 180 degrees")
move_to_angle(servo, 180)
sleep(1)

servo.detach()
print("Done")

### PATTERN 5 - SERVO SWEEP

Use for scanning motion or testing full servo range.

from gpiozero import Servo
from time import sleep

PIN = 18
STEPS = 20
DELAY = 0.05

servo = Servo(PIN)

print("Sweeping forward")
for i in range(STEPS + 1):
    servo.value = (i / STEPS) * 2 - 1
    sleep(DELAY)

print("Sweeping back")
for i in range(STEPS, -1, -1):
    servo.value = (i / STEPS) * 2 - 1
    sleep(DELAY)

servo.detach()
print("Done")

### PATTERN 6 - PASSIVE BUZZER TONE

Use for generating audio tones from a passive buzzer.

Passive buzzer wiring:
    - One pin to GPIO (signal)
    - Other pin to GND

Important:
    - Passive buzzers need PWM to produce sound.
    - Active buzzers have internal oscillators.
    - Active buzzers only need on/off (use digital_output).
    - If buzzer makes only one fixed tone regardless of frequency,
    it is an active buzzer not a passive one.
    - Default tone range is A3 to A5 (about 220 to 880 Hz).
    Tones outside this range raise ValueError.
    Set mid_tone and octaves to extend it.

from gpiozero import TonalBuzzer
from time import sleep

PIN = 23    # any safe GPIO - hardware PWM not needed for buzzer

buzzer = TonalBuzzer(PIN)

print("Tone A4 at 440 Hz")
buzzer.play(440)
sleep(1)
buzzer.stop()
sleep(0.2)

print("Tone C5 at 523 Hz")
buzzer.play(523)
sleep(1)
buzzer.stop()
sleep(0.2)

print("Tone G5 at 784 Hz")
buzzer.play(784)
sleep(1)
buzzer.stop()

print("Done")

### PATTERN 7 - PASSIVE BUZZER SIMPLE MELODY

Use for playing a sequence of tones.

from gpiozero import TonalBuzzer
from time import sleep

PIN = 23    # any safe GPIO - hardware PWM not needed for buzzer

buzzer = TonalBuzzer(PIN)

notes = [262, 294, 330, 349, 392, 440, 494, 523]
names = ["C4", "D4", "E4", "F4", "G4", "A4", "B4", "C5"]

for i in range(len(notes)):
    print("Note: " + names[i])
    buzzer.play(notes[i])
    sleep(0.4)
    buzzer.stop()
    sleep(0.1)

print("DONE")

### SERVO PULSE WIDTH ADJUSTMENT

Some servos do not reach full range with default settings.
Default gpiozero pulse widths: 1ms minimum, 2ms maximum.
Some servos use 0.5ms to 2.5ms range.

Adjust if servo does not reach full mechanical range:

from gpiozero import Servo

servo = Servo(
    18,
    min_pulse_width=0.5/1000,
    max_pulse_width=2.5/1000
)

Only adjust if default range is insufficient.
Check your servo datasheet for correct pulse widths.

### COMMON MISTAKES

1. Servo jitters or moves randomly.
Fix: use GPIO 18 for hardware PWM.
Software PWM on other pins is not stable enough.
2. Servo does not reach full mechanical range.
Fix: adjust min_pulse_width and max_pulse_width.
Check servo datasheet for correct values.
3. Pi resets or reboots when servo moves.
Fix: servo drawing too much current from Pi 5V.
Use an external 5V supply for servo power.
Connect external supply GND to Pi GND.
4. LED at 0.5 value looks much dimmer than expected.
Fix: this is normal. Human vision is logarithmic.
0.1 appears roughly half as bright as 1.0.
This is expected behavior of PWMLED.
5. Buzzer makes only one fixed tone with TonalBuzzer.
Fix: this is an active buzzer, not a passive one.
Active buzzers ignore frequency.
Use OutputDevice on/off instead. See digital_output.
6. Servo keeps jittering after script finishes.
Fix: call servo.detach() before script ends.
This stops the PWM signal cleanly.
7. PWMLED value causes TypeError.
Fix: value must be a float between 0.0 and 1.0.
Use led.value = 0.5 not led.value = 50.
8. ValueError: tone is out of the device's range.
Fix: the requested tone is outside the TonalBuzzer range.
Default range is A3 to A5 (about 220 to 880 Hz).
Keep tones inside the range, or widen it with mid_tone and octaves.

### SUMMARY

- Use this skill for variable control outputs only.
- Use PWMLED for LED brightness on any safe GPIO pin.
- Use Servo for servo control on GPIO 18 only.
- Use TonalBuzzer for passive buzzer tones.
- Use digital_output skill for active buzzers and relays.
- Always call servo.detach() when servo is not moving.
- Never power servo from a GPIO pin or from 3.3V.
- Use external 5V supply if Pi resets during servo motion.
- GPIO 18 is the conventional servo pin.
- gpiozero uses software-timed PWM by default (expect a fallback warning).
- pigpio hardware PWM is not available on the Pi 5.
- TonalBuzzer default range is A3 to A5; tones outside it raise ValueError.
- Software PWM is acceptable for LEDs and buzzers.
